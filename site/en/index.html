01 / The problem

Agents write code on their own.
But they stop at every step.

“I had complete development plans, but the agent waited for me to tell it to continue. I was the bottleneck.”

Adrian Chiriac · creator of AutoLoop

Before

A Python script, Codex Autonomous Loop: a JSON plan, Codex only, terminal only. It worked, but every run had to be prepared by hand.

Now

An app with a window: pick a Markdown or text plan, pick Codex or Claude and press Start. Progress is clear at a glance, and you can stop whenever you want.

02 / How it works

One block at a time,
until the plan is done.

01

The plan in blocks

Markdown headings, numbered lists or checkboxes: AutoLoop splits the plan by itself. Boxes already ticked count as done.

02

One invocation at a time

Each time a fresh Codex or Claude session, with the plan, the current block and the memory in PROGRESS.md.

03

Check and commit

When the agent says it is done, your check command runs. Only if it passes does the commit happen, and the loop moves on.

04

Relaunch and limits

If it stops, it is relaunched. If it stays silent too long, it is stopped. If the quota runs out, it waits and tries again.

AUTOLOOP_STATUS: DONE → check, commit, next block  ·  CONTINUE → relaunch on the same block  ·  BLOCKED → pause, or skip it
03 / The app

Hours of agent work,
readable at a glance.

Progress

Blocks grouped by state, each with its invocations, duration and tokens.

  • Done, In progress, Blocked, To do and Skipped
  • Stop after this block, to review the work before resuming
  • Any block can be marked done, queued again or skipped

Activity

For each block, the agent's invocations: messages, commands, checks, commits and outcome.

  • Commands shown as the agent wrote them, with paths relative to the project
  • Filters to show only messages, commands or events
  • Kept from one launch to the next

The timeline map

At the bottom, the whole run on one line: each icon is a message, a command or an outcome, at the moment it happened. A click jumps to the matching line in Activity.

Per-project settings

Each folder remembers its own: agent, model, check, rules. Every field has an ⓘ explaining what it does.

Accounts and profiles

Several Codex and Claude accounts, kept apart from the system ones. Sign-in goes through the CLI's official flow.

Protected mode

By default the agent works in a sandbox limited to the project folder. Full access is opt-in.

06 / What I learned

Giving an agent autonomy
means deciding when it stops.

01

Limits first

Attempts, time limits, checks and pause after a block: these rules are what make it safe to let it work alone.

02

A run must be readable

If after an hour you cannot tell where the agent got to, autonomy is useless. Groups, invocations and the map come from this.

03

Test with the real agent

Tests with a fake agent are not enough: running the real Codex and Claude found problems the tests could not see.
